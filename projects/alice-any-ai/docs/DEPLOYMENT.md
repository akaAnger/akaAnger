# Docker, VPS и устройство проекта

Для новичка: [облачная установка](CLOUD.md). Для проверки на компьютере: [локальная установка](LOCAL.md).

## Docker Compose

В папке проекта:

```sh
docker compose up -d --build
```

Панель слушает только локальный интерфейс хоста: `http://127.0.0.1:8787`. Порт не публикуется на `0.0.0.0` хоста.

Посмотреть автоматически созданный ключ администратора **на своем компьютере**:

```sh
docker compose exec app node -e "console.log(JSON.parse(require('fs').readFileSync('/app/.data/config.json','utf8')).adminToken)"
```

Вставьте его в панель. Не публикуйте вывод команды. Ключ модели вводится через панель. Для Алисы нужен отдельный HTTPS-прокси или туннель до этого порта. В контейнере cloudflared не установлен.

Если Ollama запущена на хосте, можно попробовать `http://host.docker.internal:11434/v1`. Однако ее сервер должен принимать соединения с Docker-сети. На Linux при привязке Ollama только к `127.0.0.1` этот путь не заработает автоматически. Не открывайте Ollama во внешний интернет ради исправления; настройте ограниченный интерфейс и firewall, либо запускайте приложение Node непосредственно на хосте.

Остановка без удаления настроек:

```sh
docker compose down
```

`docker compose down -v` удалит постоянный том вместе с ключами и настройками. Для обычной остановки флаг `-v` не нужен.

## VPS

Нужен постоянно работающий Node.js-процесс, не одноразовая функция. Запускайте через менеджер процессов, например systemd, от непривилегированного пользователя. Перед ним — HTTPS reverse proxy с корректным сертификатом. Приложение оставляйте на loopback, если прокси на том же сервере.

Не сохраняйте секретный путь вебхука в access-log прокси. Установите ограничение размера тела не выше 32 КиБ. В `PUBLIC_URL` укажите внешний HTTPS-домен без пути. Прокси не должен требовать браузерной авторизации или капчи для пути вебхука.

Для публичного прослушивания Node укажите `HOST=0.0.0.0`, но отдельно ограничьте доступ на сетевом уровне и используйте HTTPS снаружи. При таком HOST секреты в логи старта не выводятся: задайте `ADMIN_TOKEN` сами или получите его из защищенного файла конфигурации.

## Конфигурация

В `.data/config.json` хранятся настройки и секреты. `DATA_DIR` меняет расположение папки. Переменные `ADMIN_TOKEN`, `WEBHOOK_SECRET`, `PUBLIC_URL` (либо `RENDER_EXTERNAL_URL`) имеют приоритет при старте. Изменения API-ключа, модели, ID навыка и остальных параметров записываются через панель.

Параметры `waitMs` (0–1800, по умолчанию 1500) и `timeoutMs` (1000–120000, по умолчанию 60000) рассчитаны на опытного пользователя. Их можно менять в конфигурации остановленного приложения. Не увеличивайте `waitMs` до таймаута Алисы: нужен запас на сеть.

`dailyLimit` ограничивает число попыток, а не сумму счета. Счетчик общий для навыка и теста из панели, в памяти процесса, по UTC; сбрасывается при перезапуске. Отмена запроса не возвращает использованный счетчик.

## Архитектура

```text
Станция / приложение
        │ голос → текст (Яндекс)
        ▼
Яндекс Диалоги
        │ HTTPS POST /alice/<случайный секрет>
        ▼
Node-сервер ← защищенная панель настройки
        │ один HTTP-запрос, без инструментов
        ▼
Chat Completions / Anthropic Messages / локальная Ollama
        │ текст
        ▼
Короткий ответ сейчас ИЛИ «Ответ готов?» следующим запросом
```

| Файл | Назначение |
|---|---|
| `start.mjs` | Запуск, постоянная конфигурация, необязательные браузер и туннель |
| `src/config.mjs` | Пресеты, проверка адресов, секретов, лимитов, запись конфига |
| `src/provider.mjs` | Форматы API, таймаут, разбор ответов и безопасные ошибки |
| `src/skill.mjs` | Сессии, очередь, повторные запросы, контекст, команды |
| `src/server.mjs` | HTTP, аутентификация панели, проверка вебхука |
| `web/` | Панель без сторонних библиотек и CDN |
| `test/` | Тесты без действующих API-ключей |

В разработке:

```sh
npm run check
npm test
```

`npm install` не требуется: используются стандартные модули Node.js. GitHub Actions проверяет синтаксис и тесты отдельно от развертывания.

## Перенос в самостоятельный репозиторий

Скопируйте **содержимое** папки `projects/alice-any-ai` в новый репозиторий, например `akaAnger/alice-any-ai`. Не копируйте `.data` и `.env`. В новом корне уже есть `render.yaml`, который не содержит `rootDir`.

После переноса обновите ссылки в README и CLOUD.md на фактический новый репозиторий и добавьте CI из корневого репозитория профиля, убрав `working-directory` и фильтр вложенной папки. Не публикуйте анонс со ссылкой на еще не созданный репозиторий.
