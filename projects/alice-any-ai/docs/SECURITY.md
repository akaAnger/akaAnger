# Безопасность и приватность

## Модель доверия

Это личный неофициальный переходник для приватного навыка. Не открытый публичный ИИ-сервис и не платформа с изоляцией произвольных клиентов. Администратор панели имеет право выбирать API-адрес и отправлять туда настроенный ключ. Поэтому компрометация ключа администратора означает компрометацию этого экземпляра.

Здесь нет инструментов выполнения команд, просмотра файлов по запросу модели, управления умным домом, платежей или вызова произвольных функций. Ответ модели превращается только в текст.

## Три разных секрета

- **API-ключ провайдера** оплачивает запросы. Хранится на сервере и не возвращается панелью после сохранения.
- **ADMIN_TOKEN** открывает панель настройки. Это Bearer-токен. В локальном режиме приложение показывает личную ссылку с фрагментом `#...`, затем интерфейс удаляет фрагмент из адресной строки. Токен остается в памяти страницы, не в localStorage.
- **WEBHOOK_SECRET** защищает путь `/alice/<секрет>`. Он виден администратору в полном Webhook URL и Яндексу в настройках навыка. Его нужно скрывать в скриншотах и журналах прокси.

Не храните эти значения в публичном GitHub, задачах CI, постах и issue. В Git исключены `.data`, `.env`, резервные файлы конфигурации и журналы.

## Защитные меры

Случайные независимые секреты по 256 бит, сравнение хешей за постоянное время, проверка `skill_id`, необязательный allowlist пользователей, ограничение JSON-тела 32 КиБ, до 256 сессий, до четырех параллельных генераций, до 20 стартов генерации в минуту на процесс и до шести на сессию. Дневной ограничитель по умолчанию — 200 попыток на процесс по UTC; проверки из панели тоже учитываются.

История ограничена пятью парами сообщений и 10 000 символов. Сессии удаляются после 20 минут бездействия. Кеш повторов ограничен 24 сообщениями на сессию; одинаковый `message_id` внутри этого кеша не запускает второй платный запрос. После перезапуска процесс не может помнить старые идентификаторы. Это не гарантия exactly-once при любых сбоях.

Ошибки провайдера переводятся в заранее заданные сообщения, а не возвращаются пользователю как сырой HTTP-ответ. Переадресации API запрещены. HTTP разрешен только для `localhost`, `127.0.0.1`, `::1` и `host.docker.internal`; иначе требуется HTTPS. При изменении адреса или провайдера сохраненный ключ автоматически не переносится.

Панель не использует сторонние скрипты, шрифты, аналитику или CDN. Есть CSP, `no-store`, запрет встраивания, проверка Origin для API и защита Bearer-токеном. Запросы модели отображаются через `textContent`, без HTML. В приложении нет access-log, который записывал бы секретный путь вебхука.

## Ограничения защиты

Секрет в URL — не криптографическая подпись запроса Яндекса. Знающий Webhook URL может подделать JSON, включая `skill_id` и пользовательский ID. Эти ID сами по себе **не доказательство подлинности**. Считайте секрет вебхука полноценным паролем.

Счетчики расходов находятся в RAM и обнуляются после перезапуска. Они не заменяют денежные ограничения у API-провайдера. Ограничьте баланс и права отдельного ключа. Размещение нескольких экземпляров умножит лимиты и сломает получение ожидающих ответов; нужен один процесс.

Папка `.data` хранит конфигурацию, включая API-ключ, **без шифрования на уровне приложения**. Права 600 на Unix не заменяют шифрование диска. Обладатель доступа к серверу, резервной копии, учетной записи хостинга или локальному компьютеру может прочитать ключи. В Windows отдельно проверьте ACL папки.

Хостинг и HTTPS-прокси могут видеть содержимое запросов и секрет в адресе. Не публикуйте их логи. Для VPS настройте ограничение входящего трафика, обновления, TLS и исключение секретных путей из access-log.

## Куда идут данные

Голос обрабатывает экосистема Яндекса. Этот сервер получает текст из JSON Диалогов. При облачном API текст вопроса и ограниченная история передаются выбранному провайдеру; при Ollama — вашему локальному процессу. Репозиторий автора и автор проекта сами по себе данные вашего развертывания не получают.

Текст диалогов хранится в оперативной памяти сервера, а не в файле конфигурации. Яндекс, хостинг или ИИ-провайдер могут иметь собственные правила хранения. Команда «Новая тема» очищает локальный контекст текущей сессии, **не удаляет данные из чужих систем**.

## При утечке

Отзовите API-ключ в кабинете провайдера. Остановите экземпляр. Замените ADMIN_TOKEN и WEBHOOK_SECRET в окружении либо конфигурации, затем перезапустите приложение. Новый Webhook URL перенесите в Диалоги. Проверьте списания. Для панели создайте новый секрет, а не пароль от аккаунта Яндекса.

Не размещайте действующие секреты в публичном issue даже для сообщения об уязвимости. Сначала отзовите ключи и подготовьте воспроизведение с фиктивными данными.
